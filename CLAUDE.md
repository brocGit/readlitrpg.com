# CLAUDE.md

Guidance for Claude sessions working in this repository, including scheduled editorial runs.

## What this is

ReadLitRPG.com: a free discovery engine, book database and news brand for LitRPG and progression fantasy. The owner approves things occasionally; Claude does the work. Read these before changing behavior:

- `docs/STRATEGY.md`: why (search, onboarding and the *Patch Notes* brand, in one flywheel).
- `docs/DESIGN.md`: how (architecture, data model, security, build plan in §20). Update it when the design changes.
- `docs/TAXONOMY.md`, `docs/QUIZZES.md`: the vocabulary, dials, stats and quizzes.
- `docs/runbooks/`: operations (account setup, admin bootstrap, author decisions, secrets, jobs).

Status: **M0 (foundations) through M8 (paid promotions, Stripe, Author Pro) are built.** M8 is off until Stripe is set up (`docs/runbooks/stripe-setup.md`). Launch (Phase 1: the verified catalog, legal and trust pages, the security checklist) is next (DESIGN §20).

## Commands

```sh
pnpm install
pnpm lint            # Biome (pnpm format to fix)
pnpm typecheck
pnpm test            # Vitest, all packages
pnpm build
pnpm check           # lint + typecheck + test + script tests + quiz, golden-set and taxonomy checks
pnpm db:generate --name <what_changed>   # after editing packages/core/src/db/schema
pnpm taxonomy        # after editing data/taxonomy.yaml (and docs/TAXONOMY.md to match)
pnpm editorial …     # editorial runs: start, pull, validate, push, finish, status, brief (docs/runbooks/editorial-runs.md)
pnpm eval:classify [proposals]   # lint the golden set, or score a run's labels against it
node scripts/quiz-tool.mjs build # after editing data/quizzes/ (CI checks the generated module is current)
```

Local dev (all three apps share `.wrangler/state`, so one local D1):

```sh
for a in web admin jobs; do cp apps/$a/.dev.vars.example apps/$a/.dev.vars; done
cd apps/web && pnpm exec wrangler d1 migrations apply DB --local --persist-to ../../.wrangler/state
pnpm dev:web      # http://localhost:4321 (sign-in links print to this console)
pnpm dev:admin    # http://localhost:4322 (see docs/runbooks/bootstrap-admin.md)
pnpm dev:jobs     # then: curl "http://localhost:8787/__scheduled?cron=*/5+*+*+*+*"
```

Browser E2E (what CI runs): build, then `astro preview` web on 4321 and admin on 4322 (and the jobs Worker with `wrangler dev --test-scheduled` on 8788), then `pnpm --filter @rlr/web run e2e`, `pnpm --filter @rlr/admin run e2e`, `pnpm --filter @rlr/web run e2e:reader`, `pnpm --filter @rlr/admin run e2e:author`, `pnpm --filter @rlr/admin run e2e:content` and `pnpm --filter @rlr/admin run e2e:money` (the last five with `E2E_JOBS=1`; money runs against the fake Stripe). `astro preview` runs as a daemon: read its output with `pnpm exec astro preview logs` and stop it with `astro preview stop`.

## Rules that matter

- **Every route has an access rule** in `apps/*/src/routes.ts`. The middleware refuses unregistered routes, and a test fails if a page has no rule. Handlers that touch owned resources call `can(actor, action, resource)` from `@rlr/core/policy`.
- **Privileged and money actions go in the audit log** (`appendAudit`). Never update or delete audit rows; the database refuses anyway.
- **Settings** are declared in `packages/core/src/settings/registry.ts` (type, default, description). The table stores overrides only.
- **Jobs**: add to `JOBS` in `packages/core/src/scheduler`, add a handler in `apps/jobs/src/jobs/`, and add a line to `docs/runbooks/jobs.md`.
- **Schema changes**: edit the Drizzle schema, run `pnpm db:generate`, review the SQL, commit both. Never edit a migration that has been applied anywhere; add a new one. Migrations are additive-first. CI fails if the schema has unmigrated changes. New tables must be added to `BACKUP_TABLES` or `BACKUP_EXCLUDED` (`packages/core/src/db/backup.ts`); a test enforces it.
- **Data conventions**: ULIDs as TEXT ids; ISO-8601 UTC strings for our timestamps (Better Auth's tables use integer ms); money in integer cents; Zod at every boundary.
- **CSP**: pages get Astro's hash-based CSP. No inline `style=""` attributes, no inline event handlers, no inline scripts except Astro's own. Use classes and Preact islands. The E2E tests fail on any CSP violation.
- **Public HTML is the same for everyone** and is edge-cached. Never read the session in a public page; personal bits load from `/api/me`.
- **Secrets**: never in the repo, never in chat, never in logs (`createLogger` redacts). `.dev.vars` is git-ignored; only `.dev.vars.example` is committed. Generate Worker secrets with `openssl rand … | wrangler secret put …` so nobody sees them.
- **No AI API keys in the app.** AI work happens in editorial runs (DESIGN §7.1): a Claude session pulls work from the editorial API and pushes proposals that the server validates. The one runtime model is Workers AI embeddings (§7.2).
- **Editorial runs change data only through proposals.** Follow `.claude/skills/editorial-run/SKILL.md`. Never print or store `EDITORIAL_TOKEN` or the `CF_ACCESS_*` values, and don't edit or commit code during a data run. A new kind of work needs an entry in `EDITORIAL_KINDS`, a schema in `packages/core/src/editorial/schemas.ts`, a handler in `apply.ts`, a payload in `payloads.ts`, a brief in `packages/editorial/src/brief.ts` and a skill.
- **No scraping** Royal Road, Amazon or Goodreads. Official APIs and public data dumps only (DESIGN §7.15). Outbound requests go through `safeFetch` with a per-call host allowlist.
- **Catalog writes go through `ingestBook`** (or `writeBookFields` / `writeBookTags` for single edits). Never update provenance-backed `books` columns directly: append a source and let precedence (DESIGN §6.4) resolve the value.
- **Nothing from model knowledge is published unconfirmed.** Seeds are drafts until the publication gate passes (DESIGN §7.15).
- **Email consent is per list** (`email_consents`); marketing mail needs an active consent, a footer from `footerFor` (signed unsubscribe link, RFC 8058 headers, postal address) and goes out on the `marketing` stream. The email consumer re-checks suppression at send time. Never mail an address from a suppression list, and never store addresses there: only their hash.
- **Cross-site POSTs** are refused by the web middleware unless the route is in `CROSS_SITE_POSTS` (`apps/web/src/routes.ts`), which is only for routes that authenticate each request themselves (a signature or a signed token), never by cookie.

## Style

- Code: TypeScript strict; Biome formats (2 spaces, double quotes, 110 columns). Comments explain why, with a DESIGN section reference when there is one.
- UI copy: plain and short. Flavor text (status screens, empty states) uses the friendly System-announcer voice from `docs/QUIZZES.md` §5; errors and instructions stay plain.
- Commits: explain what and why in plain language; end with the attribution trailer the session provides. Don't put model names in commits or code.

## Gotchas learned in M0

- A Worker's entry module may only export handlers: workerd rejects other named exports. Keep helpers in another file (see `apps/jobs/src/index.ts`).
- Biome can't see variables used in Astro templates; `biome.json` turns off the unused-variable rules for `.astro` files. Don't "fix" those imports.
- `env` from `cloudflare:workers` is typed `Cloudflare.Env`. Declare secrets by augmenting `namespace Cloudflare { interface Env { … } }`.
- `pnpm deploy` is a built-in pnpm command. Use `pnpm run deploy`.
- Web and admin previews need different inspector ports (admin uses 9230).
- In Playwright, use `button:has-text(…)`: `text=…` can match surrounding prose first.
- Don't `pgrep -f`/`pkill -f` with a pattern that also appears in your own shell command: it kills the shell. Use `pgrep -x workerd`.
- Better Auth: cookies are `__Secure-rlr.session_token` (web) and `__Secure-rlr_admin.session_token` (admin). Session hooks throw `APIError("FORBIDDEN")` to refuse with a 403.

## Gotchas learned in M1

- D1 allows **1,000 queries per Worker invocation** and **100 bound parameters per statement**. Chunk `inArray` lists (~90) and multi-row inserts (params × rows ≤ 100), and split long work across job runs (`enqueueJob`).
- `titleKey` strips retailer suffixes but keeps volume numbers; `extractVolume` treats a missing number as volume 1. Keep both in mind when touching matching.
- Queries that order by nothing come back in index order: add `orderBy` in tests.
- This cloud environment's network policy blocks openlibrary.org. Enrichment is tested against fixtures in `packages/core/test/fixtures/`.
- Local queues work across separate `wrangler dev` / `astro preview` processes that share `--persist-to ../../.wrangler/state`.

## Gotchas learned in M2

- An `ai` binding (even with `remote: false`) makes `wrangler dev` open a remote proxy and demand a Cloudflare login, which breaks local dev and CI. Embeddings use the Workers AI REST API instead.
- `UPDATE … RETURNING` rows come back in table order, not the subquery's `ORDER BY`. Sort in code (see `claimItems`).
- Admin Worker secrets that aren't in `.dev.vars` are declared in `apps/admin/src/env.d.ts`, not `wrangler.jsonc`, or they would be committed.
- CI runs only on pull requests and `main`, so check `wrangler types --check` for all three apps before pushing a branch: the jobs types had gone stale unnoticed.
- The admin E2E drives a real editorial run through the CLI (`EDITORIAL_STATE_DIR` keeps its files out of your `.editorial/`).

## Gotchas learned in M3

- A Drizzle `sql` field in `select({…})` has no column name unless you add `.as("name")`, so ``orderBy(sql`name`)`` fails with "no such column". `searchPublished` hit this.
- The web Worker keeps the match model in isolate memory and checks KV at most once a minute. After a rebuild, tests poll `/api/match` until the new model is served.
- Locally, both previews write to one SQLite file. An island still sending requests (the Match Quiz's live preview) can make the other app's next query fail with `SQLITE_BUSY`. Wait for `networkidle` before switching apps in E2E. Production D1 doesn't have this problem.
- Quiz go-live is a database decision (`quiz_status`, audited), not the `status` field in the JSON. With no row, a quiz isn't on the site. The `quiz_ready` inbox default publishes it after `quiz.auto_publish_hours`.
- Pages are cached by `routeRules` TTLs (`apps/web/astro.config.ts`). Nothing purges the web cache from the admin Worker yet, so a console change shows once the TTL runs out.

## Gotchas learned in M4

- **Drizzle maps D1 batch results through row objects**, so two selected columns with the same name (`books.slug`, `series.slug`) collapse and every later field shifts. In `db.batch`, alias repeated names (``sql`${col}`.as("series_slug")``, see `site/pages.ts`). Plain awaited queries use arrays and are fine.
- In a one-table select, Drizzle drops the table name from columns interpolated into `sql` fragments, so a correlated subquery like `where ${bookTags.tagId} = ${tags.id}` turns ambiguous and silently wrong. Write such subqueries with explicit aliases (`bt.tag_id = "tags"."id"`).
- Share images are PNGs drawn by `og.render` with resvg (WebAssembly) and the bundled DejaVu fonts: Workers have no system fonts, so SVG font stacks start with DejaVu. Card keys hash the card's content; bump `OG_VERSION` after changing a layout.
- The jobs Worker's Images binding runs locally through sharp (a miniflare optional dependency). Unit tests pass a fake binding and a Node-loaded rasterizer (`apps/jobs/test/media-og.test.ts`).
- The admin E2E with `E2E_JOBS=1` needs the jobs Worker running (`wrangler dev --persist-to ../../.wrangler/state`), as CI does. Locally, imports left queued by earlier runs sit ahead of the test's own import: cancel them first (`UPDATE catalog_imports SET status='cancelled' WHERE status IN ('queued','processing')`).
- Only the owner's uploads and Open Library covers are used (DESIGN §16.5). Never add a cover source without checking its terms.

## Gotchas learned in M5

- Astro's `security.checkOrigin` is off in the web app: the same rule runs in `src/middleware.ts` so signed webhooks and RFC 8058 one-click unsubscribes can be exempted. Don't turn Astro's back on.
- `Referrer-Policy: no-referrer` makes browsers send `Origin: null` on a page's own form posts, which the origin check refuses. Pages with tokens in the URL use `same-origin` (Base's `noReferrer` prop).
- A `client:visible` island that renders nothing on the server never hydrates (the observer watches its children). Islands that wait for `/api/me` before showing anything use `client:idle` or `client:load`.
- Confirming a subscription signs the reader in by capturing a Better Auth magic link server-side (`directSignInUrl` in `apps/web/src/lib/runtime.ts`, an `AsyncLocalStorage` slot) and redirecting to it. Don't route that link through `deliverMagicLink`.
- Queue messages are capped at 128 KB, so `rendered` emails are limited to 75 KB of HTML and 35 KB of text (`packages/email/src/types.ts`).
- Timestamps a job writes should come from its `now`, not the column default, or tests with a fixed clock (and cutoffs like "issues from the last 4 days") disagree with the database.
- Local reader E2E: `pnpm --filter @rlr/web run e2e:reader` needs published books (run the admin E2E first) and, with `E2E_JOBS=1`, the jobs Worker started with `--test-scheduled` on :8788.

## Gotchas learned in M6

- **`.astro` templates aren't type-checked**: `pnpm typecheck` runs tsc, which doesn't read them, and `astro check` needs a WebAssembly package pnpm's strict layout hides. A wrong field in a template (the author page read `verifiedAt` from a model that has `verified`) only shows in the browser, so every new page needs a step in a browser E2E.
- Biome's `useImportType` turned an Astro component used only in the template into `import type`, which builds and then crashes at render. The rule is off for `.astro` files; don't turn it back on.
- The test database enforces D1's 100 bound parameters per statement (`packages/core/src/testing/d1.ts`). Seeding the schedules broke the heartbeat once the job list passed 25; any list that grows (jobs, kinds, rows) needs chunked inserts.
- Lists of editorial kinds come from `EDITORIAL_KINDS`. A hand-kept copy in the pull schema left `import_extract` unpullable.
- A new job's `schedules` row appears on the first heartbeat after deploy. An `UPDATE schedules` before that changes nothing (the author E2E runs one heartbeat first).
- `/dashboard` sends a signed-in user without a profile to `/dashboard/start`, so messages for them (a claim sent to review) must render on the start page, not as a query on `/dashboard`.
- `possible_duplicate` and `scope_check` inbox items come from both the catalog and author submissions. Author handlers act only when `subjectType` is `submission`.
- Author notices go through the `author_notices` outbox (`notifyAuthor`), emailed by the jobs Worker. Don't send author mail from the admin Worker or the heartbeat directly.
- Browser tests that submit books use store ids unique to the run: the duplicate check rightly matches a book left by an earlier local run and sends the new one to review.

## Gotchas learned in M7

- **Drizzle binds column defaults too.** A multi-row insert sends every column, so a 10-column table with only 6 set still costs 10 parameters a row (the inventory insert hit 120). Count the table's columns, not the ones you set, when chunking under 100.
- **Anything in public HTML is shared for the cache TTL.** Ad rotation is seeded by slot and period (`stableHash`), never picked at random per request, so every reader of a cached page sees the same placement and the beacon reports what was really shown.
- **Undo lives in the audit row.** An undoable action puts `undo: {kind, …}` (`packages/core/src/undo`) in its audit diff, and inbox handlers return theirs. Audit rows can't change, so an undo appends `audit.undo` naming the row; check `withUndo` for state instead of looking for flags. A new reversible action needs a spec kind, a case in `applyUndoSpec` and `describeUndo`, and a test.
- `openInboxItem` and `appendAudit` stamp rows with the real clock, not a test's `now`. Tests that filter those rows by time windows (alerts, the weekly summary, undo's 30 days) use the real clock.
- micromark escapes raw HTML rather than passing it through. Don't write tests expecting an HTML block to survive, and don't add `allowDangerousHtml`.
- A form without `action` posts to the current URL, query string included (`/inbox?snoozed=1`), so a redirect built from the query goes back there. Pick the redirect explicitly when the result belongs elsewhere.
- Local `astro preview` doesn't cache pages by `routeRules`, so browser tests see a console change at once. Production waits for the TTL (a post, an ad or a paused campaign changes within its route's `maxAge`).
- A release dated today counts as out, not announced: news tips for announcements use dates strictly after today.
- Email has no beacon. Newsletter placements count an email send when they're queued (`countEmailSends`), and the rollup only overwrites served, viewable and clicks.
- `pnpm lint | tail` hides a failing exit code. Check lint on its own before committing.

## Gotchas learned in M8

- **The fake Stripe is local only.** `STRIPE_PROVIDER=fake` keeps Stripe objects in KV and serves a checkout and portal under `/dev/stripe/`. Its "Pay" signs the events with the local `STRIPE_WEBHOOK_SECRET` and sends them through the real webhook route, so tests use the production path. `stripeFor` refuses the fake unless `ENVIRONMENT` is `local`.
- `STRIPE_WEBHOOK_SECRET` is in web's `.dev.vars.example`, so `wrangler types` declares it. Declaring it again in `env.d.ts` is a duplicate-type error. Only `STRIPE_SECRET_KEY` (not in `.dev.vars`) is declared there, as optional.
- Money moves only through conditional updates: `transitionOrder` (from the allowed states), holds, credit spends (one INSERT…SELECT that checks the balance), Sponsored Match impressions, settling and the quarterly credit claim. A read-then-write lets two requests spend the same money. Keep them conditional.
- `credits_ledger` refuses UPDATE (and deletes younger than 7 years) in the database. Correct a balance by appending an entry.
- Stripe Checkout sessions must expire at least 30 minutes out, so `ads.hold_minutes` can't go below 30, and holds outlast their session by 4 minutes. A charge under 50¢ is refused, so `settle` uses less credit or discount to reach it.
- A product added to `AD_PRODUCTS` has no `ad_products` row until `inventory.generate` runs. Look products up with `productIdFor`, which syncs the catalog on a miss.
- Money actions in the console (refunds, credits, codes, settings) need a passkey sign-in within 15 minutes (`can(adminActor(admin), "money.refund")`). Browser tests sign the owner in with a virtual passkey right before.
- `ads.checkout_attempts_per_hour` limits the browser test too: the money E2E raises it (and the Sponsored Match score) through the settings page, then resets both.
- A `waitForURL` predicate that also matches the form's own URL (`/dashboard/promote/new` starts with `/dashboard/promote/`) passes before a refusal shows. Check for `.notice.error` first, then wait for the exact next URL.
- Browser flows that book inventory use up the local database's places: the money E2E picks the first days with a place left, so it can run again.

## Gotchas learned in the game-feel pass

- Playwright treats `disabled` **and** `aria-disabled="true"` as not enabled: a click waits, and times out when a re-render replaces the button. Controls that lock briefly (the quiz answer flash) stay enabled and ignore extra clicks in the handler.
- An entrance animation with `animation-fill-mode: both` keeps its last keyframe, which beats the cascade, so a later `:hover { transform }` never applies. Entrance animations use `backwards`.
- In the web app, DOM `append` type-checks as HTMLRewriter's `Element.append` (the Workers types are global). Use `appendChild` in island code.
- Biome's `noDescendingSpecificity` compares selectors across the whole stylesheet: put lower-specificity rules for the same element first, or give the element its own class.
- Motion lives in `styles/feel.css` (web) and `@rlr/ui` (tokens, buttons). `prefers-reduced-motion` must turn off anything new (base.css does it for all animations). The rules are in DESIGN §9.10.
- Scroll-driven animations (`animation-timeline: view()`) leave everything below the fold at their first keyframe in print, full-page screenshots and tall-viewport crawlers. Don't use them for content.
- Biome's a11y rules refuse `role="listbox"` on a `ul` (use a `div`), and flagged `aria-hidden` on a `kbd` inside a button (a `span` passes). Keep `.hits button` for tests: the combobox options are buttons with `role="option"`.
- An island that renders `null` until `/api/me` answers pushes the page down when it appears (Follow moved content 67px). Render the signed-out state while waiting, and don't read `location` in the render: the server renders islands too. Build paths from props instead.
- Astro's scoped `<style>` rules carry an attribute selector, so `nav { gap }` in Base outranks `.site-nav { gap }` in a global sheet. Override with two classes (`.site-header .site-nav`), and put page-sheet overrides (reader.css, site.css) in those sheets: they load after `feel.css`.
- `src/pages/500.astro` stands alone (no Base): the layout reads settings, and the error it reports may be the database.
- Browser tests that click through a quiz wait for the next question or the result after each click. A click on the answer just picked can land while the result renders, and Playwright then waits 30 s for a button that never comes back.
- Match tiers (`matchTier`, the names and cut-offs) live in `@rlr/ui/tokens`, so the site and the emails agree; `packages/email` depends on `@rlr/ui` for them.
- In the web app, `[tabindex="-1"]:focus` has no ring: those are headings that take focus so it can follow a quiz, not controls. Don't give a control `tabindex="-1"` and expect a visible focus.
- Astro drops whitespace that holds a line break next to a tag or an expression, so `RSS</a> ·` followed by a new line renders "RSS ·Release". End such lines with `{" "}`. A test in each app scans the templates for "·" separators (`lostSeparatorSpaces`); plain words that run into a tag on the next line need the same care.
- A page that returns a bodiless 404 (`notFound()`) is replaced by the 404 page, but Astro keeps the *original* response's headers. Middleware leaves those responses alone (`reroutesToErrorPage`): the API policy (`default-src 'none'`) once left every missing book's page without styles.
- Every console E2E run registers another passkey for the local owner. Chromium refuses a registration whose exclude list passes 64, so the E2Es delete the owner's old passkeys first (a fresh CI database never gets there).
